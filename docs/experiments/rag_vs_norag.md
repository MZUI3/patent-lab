# RAG 사용 전후 답변 품질 비교

## 방법
- 실행: `python -m src.eval.rag_vs_norag` → 원자료 [eval/rag_vs_norag_raw.md](../eval/rag_vs_norag_raw.md)
- **RAG 없음**: 같은 모델(`gpt-4o-mini`, 같은 전문가 역할)에 특허 명칭·출원번호와 질문만 준다.
- **RAG 사용**: 문서 수집 → 근거 검색(MMR, k=5) → 근거 기반 답변 파이프라인.
- 대표 질문 6개: 근거 없이 답하면 틀리기 쉬운 질문 4개(청구항 구성, 서지 사항, 진단 원리, 고장 유형) + 수집한 문서로 답할 수 없는 질문 2개.
- 정답 확인: RAG 답변의 사실은 KIPRIS 서지 상세(요약·청구항 원문)와 직접 대조했다.

평가 기준 
1. **사실 정확성** — 원문과 맞는가
2. **근거 제시** — 어느 문서에서 왔는지 댈 수 있는가
3. **모르는 것을 모른다고 답하는가**

## 해석
- **가장 위험한 것은 그럴듯한 오답이다.** Q3·Q4에서 RAG 없는 답은 반도체 테스트 일반론으로는 자연스럽지만 해당 특허의 내용과 다르다. 특허 조사에서 이런 답은 다른 특허와 혼동하게 만든다.
- **RAG 없이도 모른다고는 잘 답했다.** 모델이 특정 특허 정보를 모른다는 것을 알고 Q2·Q5·Q6에서 답을 피했다. 다만 Q1처럼 "일반적으로는…"으로 이어가며 원문에 없는 구성을 늘어놓는 경우가 있어, 거절만으로는 안전하지 않다.
- **RAG의 차이는 '확인 가능성'이다.** 같은 "모른다"라도 RAG 쪽은 수집한 근거에 없다는 뜻이고, 근거가 있을 때는 KIPRIS 원문 링크로 바로 검증할 수 있다.

## RAG 쪽에서 발견한 한계
1. **인용 위치가 덜 정확한 경우**: Q1은 청구항 1을 물었는데 청구항 청크가 아니라 요약이 담긴 메타데이터([근거 1])를 인용했다. 요약이 청구항 1과 같은 구성을 서술해 내용은 맞지만, 엄밀하게는 청구항 원문을 인용해야 한다.
2. **문장 압축**: Q4에서 학습 데이터 생성 단계를 한 문장으로 줄이며 관계가 흐려졌다.
3. **근거 범위 밖의 일반론**: 유사도 검색 설정에서는 배경 질문에 엉뚱한 근거 번호를 다는 경우가 있었다 ([mmr_vs_similarity.md](mmr_vs_similarity.md) 참고). MMR을 기본값으로 바꿔 줄였다.
