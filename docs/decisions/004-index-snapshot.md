# 004 — 색인은 Chroma 저장소가 아니라 임베딩 스냅샷으로 공유한다

**맥락** — Chroma 영구 저장소(`chroma_db/`)는 약 180MB 바이너리이고 버전·OS·경로에 묶인다. 다른 PC에서 clone 직후 바로 실행되게 하려면 색인을 함께 줘야 하는데, 1만 건을 다시 임베딩하면 API 비용과 시간이 든다.

**결정** — 컬렉션의 ID·본문·메타데이터(json.gz)와 임베딩(float16 npz)을 `data/index/`에 저장하고(약 23~33MB), 색인이 비어 있으면 앱이 자동으로 복원한다(약 20초, 외부 호출 0회). float16으로 줄여도 복원본의 검색 상위 10건이 원본과 순서까지 같았다 (자동 점검 `snapshot-restore`).

**함께 겪은 문제** — Chroma(Rust)가 Windows에서 한글이 든 절대 경로의 HNSW 인덱스 파일을 읽지 못해 "Error loading hnsw index"가 나고 검색 결과가 최근 추가분만 나왔다. 처음엔 ASCII 경로의 임시 폴더에서 시험해 재현되지 않았고, 컬렉션이 커져 인덱스가 디스크에 쓰인 뒤에만 드러났다. 저장소를 ASCII 경로(상대 경로·8.3 짧은 경로)로 열도록 고치고, 색인 검색 상위 10건이 전수 계산과 일치하는지 보는 점검(`index-vs-bruteforce`)을 추가했다.

**추가 결정 (2026-10-24)** — 임베딩 모델을 바꾸면 스냅샷의 벡터와 질문 벡터가 맞지 않아 검색이 조용히 틀어진다. 스냅샷에 `manifest.json`(임베딩 제공자·모델·차원·건수)을 기록하고, 현재 설정과 다르면 복원을 거부하고 재색인 절차를 안내하게 했다.

**주의** — 스냅샷에는 KIPRIS에서 받은 특허 텍스트가 들어 있다. 저장소를 공개하거나 배포하기 전에 KIPRIS Plus 재배포 조건을 확인한다.
