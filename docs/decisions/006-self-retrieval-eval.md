# 006 — 라벨 없이 선행기술 조사를 자동 평가한다 (자기 청구항 기반)

**맥락** — 검색 방식·모델·후보 수를 바꿀 때 "좋아진 것 같다"가 아니라 수치로 비교하고 싶었다. 그러나 사람이 라벨링한 "아이디어 ↔ 선행 특허" 쌍이 없고, 특허 심사관 인용 문헌 같은 외부 정답도 쓰는 API에서는 받을 수 없다.

**결정** — 청구항이 캐시된 특허 40건의 첫 청구항을 LLM이 "엔지니어가 동료에게 아이디어를 설명하듯" 2~4문장으로 바꿔 쓴 문장을 입력으로 쓰고, **그 특허 자신을 정답**으로 둔다 (`make_prior_art_cases.py`). 청구항을 베끼면 검색이 너무 쉬워지므로 베끼지 않게 지시하고, 실제로 겹친 가장 긴 구절 길이를 사례마다 기록한다(중앙값 8자). 평가 중에는 KIPRIS를 호출하지 않는다(검색 확장 끔, 청구항은 캐시된 것만).

**지표** (`prior_art_eval.py`)
- 검색: Recall@20(후보), Recall@5(대비 대상), MRR@5
- 판정: 정답 특허에 대한 개시율 — 자기 청구항이므로 전부 "개시"가 정답. 낮으면 판정이 엄격하거나 원문 구절 검증이 맞는 판정을 떨어뜨리는 것
- 정렬: 겹침 1위율
- 비용: 사례당 시간·토큰·추정 비용
- 실행마다 [요약표](../eval/prior_art_eval.md)에 한 줄이 쌓여 설정 변경 전후가 비교된다. 사례별 결과와 틀린 판정 목록은 실행별 문서에 남긴다.

**한계** — 정답이 자기 자신이라 **검색의 상한과 판정의 일관성**을 재는 것이지, 진짜 선행 특허를 찾는 능력을 재는 것은 아니다. 외부 정답이 생기면 사례에 더한다.

**결과** — 기준선에서 바로 두 가지 원인을 찍어냈다: 검색 미스 5건 중 2건은 MMR이 정답을 떨어뜨린 것([003](003-mmr-for-qa-evidence.md) 재검토), 판정 오류 6개 중 4개는 원문 구절 검증의 거짓 음성([002](002-quote-verification.md) 후속).
