# 007 — 사전 수집 + 조사할 때 KIPRIS 검색으로 대상을 넓힌다

**맥락** — KIPRIS Plus 무료 키는 월 호출 한도가 있고(1,000회), 응답 형식도 두 가지(`inventionTitle` / `InventionName`)가 섞여 온다. 반도체 테스트 분야만 미리 받으면 다른 분야 아이디어는 조사할 수 없고, 전 분야를 미리 받는 것은 한도 안에서 불가능하다.

**결정**
- 반도체 테스트(IPC G01R 31/3183)는 전체 985건, 다른 8개 분야는 대표 IPC에서 각 1,000건만 미리 받는다 (18회 호출).
- 선행기술 조사 때마다 아이디어에서 키워드 1~2개를 뽑아 KIPRIS 초록 검색(적으면 전체 텍스트 검색)을 하고, 처음 보는 특허를 색인에 더한다. 검색 1회 100건으로 제한해 조사 시간을 약 100초 → 45~50초로 줄였다.
- 검색·상세 응답은 전부 파일로 캐시하고 모든 호출을 `api_calls.log`에 기록한다. 같은 키워드·같은 특허는 다시 호출하지 않는다.
- 색인 여부는 파일 기록이 아니라 컬렉션 기준으로 본다 — 기록 후 색인 전에 실행이 멈추면 "이미 본 특허"로 남아 빠지는 문제를 겪었다(38건 누락 → 수정 후 채워짐).
- 응답 태그 차이는 표준 필드명 → 태그 후보 매핑(`KEY_MAP`)으로 둘 다 읽는다. 오류 메시지에 `ServiceKey`가 든 URL이 섞이는 문제는 공통 호출기에서 키를 `***`로 가려 올린다.

**결과** — 현재 10,284건(일괄 8,747 + 검색 수집 1,537). 배터리 열폭주처럼 미리 받지 않은 분야 아이디어도 조사 1회로 관련 특허 38건이 추가되어 1위가 나왔다.

**한계·후속** — 일반적인 키워드("신경망 고장 위치 예측")는 다른 분야 특허를 수천 건 쏟아낸다. 키워드에 아이디어의 핵심 대상(스캔 체인·배터리 셀 등)을 넣도록 프롬프트를 고쳤지만, 검색 수집 특허가 많아질수록 반도체 외 분야의 사전 수집 1,000건씩이 필요한지는 평가셋으로 다시 볼 수 있다.
