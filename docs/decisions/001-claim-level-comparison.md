# 001 — 선행기술 조사는 청구항 단위로 대비한다

**맥락** — 특허 출원 전 선행 조사에서 가장 오래 걸린 일은 비슷한 특허를 찾는 것이 아니라, 찾은 특허의 청구항을 읽으며 내 아이디어의 구성요소가 하나씩 나와 있는지 대조하는 것이었다. 특허의 권리 범위는 요약이 아니라 청구항이 정한다.

**선택지**
1. 아이디어와 특허 요약의 유사도만 보여준다 (구현 쉬움, 근거 약함)
2. 아이디어를 구성요소로 나누고 특허의 **청구항**과 구성요소별로 대비한다 (KIPRIS 서지 상세 호출 필요, 프롬프트 설계 필요)

**결정** — 2. 아이디어 → 구성요소 3~6개(`IDEA_ELEMENTS`) → 후보 선별(`PRIOR_ART_SELECT`) → 특허별 청구항 수집 → 구성요소마다 개시/일부/미개시 판정(`ELEMENT_COMPARE`). 겹침 비율 = (개시 1 + 일부 0.5) / 구성요소 수로 정렬한다. 결과는 신규성·진보성 판단이 아니라는 전용 면책 문구를 결과 위에 띄우고, 요약 프롬프트에서 "새롭다/차별화된다" 같은 평가를 금지했다.

**결과** — 실제 특허 실무의 클레임 차트와 같은 형태가 되어, 사용자가 판정을 청구항 원문으로 바로 검증할 수 있다. 자동 평가에서 자기 청구항에 대한 개시율 96% ([평가](../eval/prior_art_eval.md)).

**후속** — 종속항 → 독립항 연결(claim_no, depends_on 메타데이터)과 조사 보고서(구성요소 × 특허 매트릭스) 내보내기.
