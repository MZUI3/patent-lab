# 002 — "개시" 판정은 원문 구절이 확인될 때만 인정한다

**맥락** — 선행 조사에서 가장 위험한 오류는 "이미 나와 있다"를 지어내는 거짓 개시다. 대비 프롬프트만으로는 "로그"·"학습"이 0회 나오는 특허에 "고장 로그로 학습 데이터 생성 → 개시"라고 판정하는 일이 있었다.

**선택지**
1. 프롬프트에 "추측하지 말라"를 강화한다 (효과 불안정)
2. 판정마다 **인용 구절(quote)**을 받고, 코드로 그 구절이 청구항 원문에 실제로 있는지 확인한다. 없으면 미개시로 바꾼다
3. 상위 모델로 바꾼다 (비용 증가, 거짓 개시가 사라지지는 않음)

**결정** — 2를 기본으로 하고 3을 보조로 썼다. `ELEMENT_COMPARE` 출력의 키 순서를 `quote → evidence → status`로 두어 **구절을 먼저 찾고 판정**하게 했다. 검증(`quote_found`)은 공백과 괄호 병기("스캔 체인(scan chain)")를 지운 뒤 구절의 90% 이상이 한 덩어리로 일치하면 통과시킨다. LLM이 병기를 빼고 옮기거나 조사를 하나 바꾸는 정도는 허용하기 위해서다.

**결과**
- 거짓 개시가 코드 수준에서 차단된다. 자동 점검 `prior-art-quotes`: 개시·일부 판정 전부 원문 구절 확인.
- 비용: 기준선 평가에서 정답 특허에 대한 판정 오류 6개 중 **4개가 이 검증이 맞는 판정을 미개시로 바꾼 것**이었다 (정답 특허에 대한 판정 136개 중 2.9%). 판정 이유에는 "개시되어 있다"고 쓰고 구절을 원문과 다르게 옮긴 경우다 ([기준선 해석](../eval/prior_art_eval/baseline-flash-lite_2026-10-24.md)).

**후속** — 검증 실패 시 바로 미개시로 바꾸지 않고 구절 재탐색 1회를 두거나, 토큰 단위 일치로 바꾸고 거짓 개시가 늘지 않는지 같은 평가셋으로 확인한다.
