# 008 — 사내 문서는 검색 단계에서 열람 권한으로 거른다

**맥락** — 연구 조직에서 쓰려면 공개 특허만이 아니라 발명 신고서·실험 보고서·계약 메모처럼 볼 수 있는 사람이 정해진 문서도 검색해야 한다. 권한을 답변을 만든 뒤에 거르거나 화면에서만 숨기면, 권한 밖 내용이 이미 LLM 프롬프트에 들어간 뒤라 답변에 섞이거나 외부 API로 나간다. 권한은 "무엇을 보여줄까"가 아니라 "무엇을 근거로 꺼낼까"에서 걸러야 한다.

**선택지**
1. 사용자·팀마다 컬렉션을 나눈다 — 여러 팀에 열린 문서는 중복 색인되고, 권한이 바뀌면 문서를 옮겨야 한다
2. 검색 결과를 받은 뒤 코드로 거른다 — 상위 k개가 권한 밖 문서로 차면 근거가 비고, 거르는 코드를 한 곳이라도 빠뜨리면 그대로 샌다
3. 문서마다 열람 주체를 청크 메타데이터에 펼쳐 두고, 사용자의 주체 목록으로 만든 필터를 벡터 DB 질의 자체에 넣는다

**결정** — 3에 검색 뒤 이중 확인을 더했다.
- 주체 표기: `all`(외부 방문자 포함) · `employee` · `team:<팀>` · `role:<역할>` · `user:<아이디>`. 사용자는 자기 역할·팀·아이디에서 주체 목록을 얻는다. Chroma 메타데이터는 리스트를 받지 않아 주체마다 불리언 키(`acl_team_dft: true`)로 펼치고, 질의 필터는 사용자 주체들의 `$or`다 (`src/security/acl.py`).
- 검색 결과마다 `can_read`로 한 번 더 확인한다. 필터를 빠뜨린 저장소를 흉내 낸 테스트에서도 권한 밖 청크가 걸러진다.
- 등급·열람 주체는 원본 파일이 아니라 카탈로그(`data/internal/catalog.yaml`) 한 곳에서 관리한다. 등급과 주체가 어긋나면(기밀인데 `employee`, 내부인데 `all`) 그 문서는 색인하지 않는다 — 설정이 틀린 문서가 넓게 열리는 것보다 안 보이는 쪽이 낫다. 카탈로그에 없는 파일도 색인하지 않는다.
- 색인 동기화는 내용·등급·열람 주체·버전·제목을 함께 해시한 지문으로 바뀐 문서를 찾는다. 권한만 바뀌어도 다시 색인된다 — 색인에 옛 권한이 남으면 권한을 거둔 사람에게도 계속 검색되기 때문이다.
- 시스템 관리자(`admin`)도 문서는 자기 주체로 열람 권한이 있는 것만 본다. 운영 현황(감사 로그 집계)을 보는 권한과 연구 문서를 읽는 권한을 나눴다.

**결과** ([보안 평가](../eval/security_eval.md))
- 권한 밖 노출: 계정 5개 × 표적 질문 12개 중 그 문서를 볼 수 없는 조합 38쌍 — **권한 필터 0/38**, 필터 없이 검색하면 38/38에서 표적 문서가 근거 상위 5개에 들어왔다.
- 정당한 접근은 22/22 유지. 권한 필터를 켠 사내 문서 검색 Recall@5 100%, MRR 0.964 (14문항).
- 단위 테스트: 권한을 거두면 바로 검색되지 않음, 내용이 바뀌었는데 버전이 그대로면 경고, 카탈로그에서 빠진 문서는 색인에서 삭제.

**한계·후속** — 계정·팀은 TOML 파일로 관리한다. 사내 SSO(OIDC)를 붙이면 IdP의 그룹 클레임을 주체 목록으로 바꾸면 된다(Streamlit `st.login`). 가상 문서 11건(13청크)이라 필터 없는 검색이 거의 항상 새는 조건이다 — 문서가 많아지면 "필터 없이 몇 %가 새는가"는 낮아지겠지만, 필터를 켠 0건은 문서 수와 상관없이 지켜져야 하는 값이다.
