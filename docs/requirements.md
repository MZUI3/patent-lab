# 요구사항 정의서 — Patent Lab (RAG 기반 선행기술 조사 서비스)

## 1. 도메인 확정
**도메인**: 한국 특허 선행기술 조사 — 중심 분야는 반도체 테스트(IPC **G01R 31/3183**: 테스트 패턴 생성·스캔·BIST 등). 아이디어가 어느 분야든 조사할 수 있도록 8개 분야 대표 특허를 함께 두고, 조사할 때 KIPRIS 전 분야를 키워드로 검색해 특허를 더한다.

**선택 이유** — 이 분야에서 특허를 출원하며 선행 특허 조사를 직접 해 보았다. 비슷한 특허를 찾는 것보다, 찾은 특허의 청구항을 하나씩 읽으며 "내 아이디어의 어느 구성이 이미 나와 있는가"를 대조하는 데 시간이 가장 많이 들었다. 이 대조는 청구항 원문을 근거로 해야만 의미가 있으므로, 근거를 함께 보여주는 RAG가 그대로 들어맞는 문제다. 그래서 **선행기술 조사**를 이 서비스의 중심 기능으로 두었다.

### 도메인 선택 조건 충족 근거
| 조건 | 충족 근거 |
|---|---|
| **항목 메타데이터 약 100건 이상** | KIPRIS Plus 검색 API로 **10,284건** (2026-10-22): 반도체 테스트 IPC G01R 31/3183 전체 985건 + 반도체 소자(H01L)·전지(H01M)·컴퓨팅(G06F)·인공지능(G06N)·디지털 통신(H04L)·의료 진단(A61B)·전기차(B60L)·재료 분석(G01N) 각 약 1,000건 + 선행기술 조사 중 키워드 검색으로 받은 1,537건. 항목마다 명칭·출원인·출원번호·출원일·IPC·등록 상태·요약 보유, 빈 명칭·요약 0건 |
| **외부 문서 출처** | ① 항목 자체 문서: KIPRIS Plus 서지 상세 API의 **요약·청구항** (모든 특허에 존재). 이 API는 명세서 상세 설명(공보 본문)을 주지 않으므로, 권리 범위를 정하는 청구항을 공보 문서로 쓴다 ② 개념 문서: 한국어 위키백과 (지터·내장 자체시험·자동 시험 패턴 생성(ATPG)·적분회로·비교기 등). 이용 조건은 아래 5절 |
| **근거가 필요한 질문** | 아래 질문들은 특허 문서 밖 일반 지식으로 답하면 틀린다. 근거 없이 답하게 한 실험에서 사실 질문 4개 모두 오답 또는 무응답 ([F2015](f2015_rag_comparison.md)) |

**근거 없이 답하면 틀리거나 위험해지는 질문 예**
1. "지터 측정 회로 특허(1020230136220)의 청구항 1에 포함된 구성 요소는?" — 근거 없이 답하면 발진기·ADC 등 일반적인 구성을 늘어놓지만, 실제 청구항은 멀티플렉서·검출 회로·제1 가산기·적분 회로·피드백 회로·비교기다.
2. "스캔 체인 다중 고장 진단 특허(1020210190872)는 어떤 원리로 진단하나?" — 근거 없이는 "출력 신호 비교"라는 그럴듯한 오답, 실제는 전압 입력에 의한 스캔 셀 간 데이터 복사.
3. "기계 학습 기반 스캔 체인 진단 특허(1020230005129)가 판별하는 고장 유형은?" — 근거 없이는 "논리 결함·연결 결함 등" 추측, 실제는 천이지연고장.
4. "이 특허의 출원인·출원일·현재 등록 상태는?" — 근거 없이는 답하지 못한다. 상태(등록·소멸·취하 등)는 시간에 따라 바뀌어 모델 지식으로는 알 수 없다.
5. "스캔 체인 고장 로그로 학습 데이터를 만들어 고장 셀을 예측하는 내 아이디어와 겹치는 선행 특허는? 어느 구성이 겹치나?" — 선행기술 조사 질문. 근거 없이 답하면 존재하지 않는 특허나 청구항을 지어낼 수 있어 가장 위험하다. 이 서비스는 겹친다는 판정마다 청구항 원문 구절을 대고, 원문에서 확인되지 않는 판정은 받아들이지 않는다.

**판단이 위험한 도메인인지**: 건강·금융은 아니지만, 특허는 **권리 범위·침해·등록 가능성 같은 법적 판단**과 맞닿아 있어 잘못된 답이 사업·법률 판단으로 이어질 수 있다. 따라서 면책 안내를 둔다.
> 이 서비스는 특허 정보 탐색을 돕는 도구이며, 권리 범위·침해·등록 가능성 등에 대한 법률 자문을 대신하지 않습니다. 법적 판단은 변리사 등 전문가에게 확인하세요.

(사이드바에 항상 표시, 선행기술 조사 결과에는 "신규성·진보성 판단이 아님"을 담은 별도 면책 표시, 답변·해설·대비 프롬프트에서 법적 평가를 금지)

## 2. 기획 요약
| 항목 | 결정 |
|---|---|
| 항목 텍스트 (2.2) | 발명의 명칭 · 출원인 · 출원번호 · 출원일 · IPC · 등록 상태(등록번호·등록일) · 요약을 줄 단위로 묶음. 요약을 넣어 기술 내용으로 찾을 수 있게 함 |
| 컬렉션 (2.3) | `patent_meta`(특허 10,284건, 분야 필드 포함, ID=출원번호) / `patent_docs`(공보·위키 청크, ID=`출원번호:문서ID:순번`, `item_id` 필터) |
| 프롬프트 (2.4) | ① 검색어 추출(JSON 문자열 배열) ② 후보 선별(JSON 정수 배열) ③ 답변 생성(`[근거 n]`, 없으면 "확인되지 않습니다") |
| 검색 설정 (2.5) | 청크 1,000자 / 중복 200자, Top-k 5(+메타 1), MMR(후보 30, λ 0.5) — 모두 `src/config.py` |
| 서비스 기능 (2.6) | 화면: 선행기술 조사가 첫 화면, 결과 카드 → 특허 패널(구성요소 대비·질문하기·청구항 해설) / 특화 기능: ① 선행기술 조사(아이디어 ↔ 선행 특허 청구항 구성요소 대비, KIPRIS 키워드 검색으로 대상 확장) ② 청구항 해설 / 조건 탐색: 연도 필터 + 메타데이터 검색 + LLM 조건 선별 / 안내: 진행 상태, 색인 없음·키 누락, 면책 문구(선행기술 조사는 별도 면책) |

자세한 설계는 [RAG 파이프라인 설계문서](rag_pipeline_design.md).

|---|---|---|---|---|---|
| NF2001 | 성능 | 응답 시간 | 대표 질문의 전체 처리 시간이 사용에 지장이 없어야 한다 | 문서는 질문 시 필요한 만큼만 수집, 외부 응답 캐시 | 질의응답: 이미 수집한 검색어 5.0~5.9초, 수집 생략 4.1초, 처음 질문하는 특허 11.8~22초 / 선행기술 조사: 캐시된 키워드 16초, 새 키워드 약 45~50초(KIPRIS 검색 100건 수집·임베딩 포함, `ONDEMAND_ROWS`로 조절) |
| NF2002 | 성능 | 수집 캐시 | 이미 수집·색인한 검색어는 다시 수집하지 않는다 | 특허별 수집 기록(검색어·문서·질문별 검색어) + KIPRIS·위키 응답 파일 캐시 | 같은 질문 재실행 시 프롬프트1 호출·외부 호출 0회, 추가 청크 0개 |
| NF2003 | 보안 | API 키 관리 | 키는 환경변수로 관리하고 소스에 넣지 않는다 | `.env` (git 제외), `.env.example` 제공, 키 읽기는 `src/env.py` 한 곳 | 추적 파일·전체 커밋 이력에서 키 값 0건 |
| NF2004 | 보안 | 내부 정보 비노출 | 화면에 키·프롬프트 전문·오류 추적을 노출하지 않는다 | 화면에는 안내 문구만, 추적은 서버 로그. 오류 메시지의 KIPRIS 키는 `***`로 가림 | 처리 중 오류 → "처리 중 오류가 발생했습니다"만 표시 (AppTest). 예상하지 못한 오류도 `.streamlit/config.toml`의 `showErrorDetails = "none"`으로 경로·코드 미표시 (브라우저 확인) |
| NF2005 | 확장성 | 모듈 분리 | 수집·색인·검색·생성·UI 책임을 분리하고 도메인 의존 부분은 데이터 준비 영역에 모은다 | `data_prep / vectorstore / rag / service / ui` | KIPRIS·위키 코드는 모두 `data_prep/` |
| NF2006 | 품질 | 외부 API 예절 | 재시도·호출 간격을 지키고 출처가 요구하는 식별 정보를 포함한다 | `data_prep/http.py`: 최대 3회 재시도(1·2·4초 대기), 성공 후 0.5초 간격, 모든 호출 기록. 위키 User-Agent에 연락처 | `data/raw/api_calls.log`에 호출마다 기록 |
| NF2007 | 법·윤리 | 출처와 이용 조건 | 수집한 데이터와 문서의 출처와 이용 조건을 기록하고 지킨다 | 아래 5절, README 4절. 근거마다 원문 링크 표시. 수집 데이터는 교육용 저장소에만 두고 공개·배포 전 약관 확인 | 위키 근거에 제목·URL 표시 (CC BY-SA 출처 표시) |
